Proxmox: Container / VM vorbereiten

Debian 12 / Ubuntu 24.04 mit Docker & Node.js 22 LTS

Wichtig bei Proxmox LXC-Containern:
Wenn du einen schlanken LXC-Container erstellst, öffne im Proxmox-Webinterface den Container → Options → Features → Haken bei Nesting (Verschachtelung) und keyctl setzen. Nur damit kann Docker innerhalb des Containers Container für Node.js-Apps und Multiplayer-Server starten!

Öffne die Shell deines neuen Proxmox-Servers und führe folgenden Befehl aus, um alles Nötige auf einmal zu installieren:

Terminal • Basissystem, Docker & Node.js 22 
apt update && apt install -y curl git docker.io build-essential
systemctl enable --now docker
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs

• Prüfe danach kurz mit node -v (sollte v22.x ausgeben) und docker ps, dass beides ohne Fehler läuft.

Cloudflare: DNS & Ursprungszertifikat

Voller Schutz mit Orange Wolke und 15 Jahre gültiges SSL-Zertifikat

Damit dein Dashboard unter run.lspx.org und jede neue App direkt unter *.lspx.org (z. B. mein-spiel.lspx.org) läuft, legst du in Cloudflare folgende zwei DNS-Einträge an:

Typ Name / Host IPv4-Adresse (Ziel) Proxy-Status (Wolke)
A run 123.45.67.89 Orange Wolke (Proxied)
A (Wildcard) * 123.45.67.89 Orange Wolke (Proxied)
Keine Sorge um bestehende Subdomains:
Spezifische DNS-Einträge (wie z. B. cloud.lspx.org oder mail.lspx.org) haben im DNS immer Vorrang vor dem Sternchen (*). Deine bestehenden Dienste bleiben zu 100 % unberührt!

15-Jahre Ursprungszertifikat in Cloudflare erstellen

  • ✓ Gehe in Cloudflare auf SSL/TLS → Origin Server → Create Certificate.
  • ✓ Prüfe, dass lspx.org und *.lspx.org als Hostnames aufgeführt sind (ist Standard).
  • ✓ Gültigkeit: 15 Jahre auswählen → Klicke auf Create.
  • ✓ Kopiere den Private Key und das Origin Certificate – du fügst sie gleich in NPM ein.
  • ✓ Gehe unter SSL/TLS auf die Übersicht und stelle den Modus auf Full (Strict).

Nginx Proxy Manager (NPM): Ursprungszertifikat & Host

Custom Certificate einfügen und Proxy Host mit WebSockets konfigurieren

1. Ursprungszertifikat einfügen (Custom Certificate)

Gehe in NPM auf SSL Certificates → Add SSL Certificate → Custom:

  • ✓ Name: Cloudflare Origin (lspx.org)
  • ✓ Certificate Key: Füge den Private Key aus Cloudflare ein.
  • ✓ Certificate: Füge das Origin Certificate aus Cloudflare ein.
  • ✓ Klicke auf Save – fertig! 15 Jahre kein Zertifikats-Stress.

2. Proxy Host anlegen

Gehe in NPM auf Hosts → Proxy Hosts → Add Proxy Host:

Domain Names run.lspx.org, *.lspx.org, lspx.org
Scheme / Forward Host / Port http://192.168.1.50:3000
Aktivieren (Details-Tab) Cache Assets: AUS (Wichtig!) Block Common Exploits: AN Websockets Support: AN (Wichtig!)
SSL-Tab Dein Cloudflare Origin (lspx.org) auswählen • Force SSL & HTTP/2 aktivieren

3. Advanced-Tab: Upload-Limits erhöhen

Füge diesen Code im Advanced-Tab ein, damit große ZIP-Uploads bis 250 MB nicht von Nginx blockiert werden:

NPM • Custom Nginx Configuration (Advanced Tab) 
client_max_body_size 250M;
proxy_read_timeout 300s;
proxy_send_timeout 300s;

SnapHost: Code auf den Server bringen & Dienst starten

Wähle: Entweder mit Git-Repository oder direkt per WinSCP / SCP

Weg A: Über Git (Empfohlen) Beste Wahl

Wenn du noch kein Git-Repo hast, erstelle es jetzt in 1 Minute lokal auf deinem PC in der PowerShell: 

# 1. Lokal im WEB2-Ordner ausführen:
git init
git add .
git commit -m "Initial SnapHost setup"

# 2. Privates Repo auf GitHub erstellen, dann:
git remote add origin https://github.com/DEIN_USER/snaphost.git
git branch -M main
git push -u origin main

Danach auf dem Proxmox-Server klonen:

git clone https://github.com/DEIN_USER/snaphost.git /opt/snaphost
cd /opt/snaphost && npm install --omit=dev
Weg B: Direkt ohne Git (WinSCP) Kein Account nötig

Du kannst das Projekt auch einfach direkt von deinem PC auf den Server kopieren:

  • ✓ Installiere WinSCP (oder FileZilla) auf deinem PC.
  • ✓ Verbinde dich per SFTP mit der IP deines Proxmox-Servers (192.168.1.50) und Benutzer root.
  • ✓ Ziehe den Ordner WEB2 einfach per Drag & Drop nach /opt/snaphost (ohne node_modules).

Auf dem Server dann Abhängigkeiten installieren:

cd /opt/snaphost
npm install --omit=dev

Produktions-.env Datei erstellen

Erstelle die Datei /opt/snaphost/.env mit deinen aktuellen Parametern:

/opt/snaphost/.env (Dynamisch generiert) 
PORT=3000
HOST=0.0.0.0
NODE_ENV=production
ROOT_DOMAIN=apps.meinedomain.de
ADMIN_SUBDOMAIN=admin
ADMIN_PASSWORD=SicheresAdminPasswort2026!
JWT_SECRET=super-geheimer-zufallsschluessel-fuer-snaphost-2026-prod
DATA_DIR=./data
DEFAULT_TTL=24h
MAX_UPLOAD_SIZE_MB=250

Systemd-Dienst aktivieren (Dauerhafter Hintergrundbetrieb)

Damit SnapHost beim Server-Neustart automatisch mitstartet:

Terminal • Systemd-Service aktivieren 
cp /opt/snaphost/snaphost.service /etc/systemd/system/snaphost.service
systemctl daemon-reload
systemctl enable --now snaphost

# Status prüfen
systemctl status snaphost
Herzlichen Glückwunsch!
Dein SnapHost ist jetzt live! Rufe im Browser https://apps.meinedomain.de auf und logge dich mit deinem Master-Kennwort ein.

Zukünftige Updates: Wie ändern wir Code?

Egal ob mit Git oder per WinSCP – in Sekunden aktualisiert

Wenn wir in Zukunft neue Funktionen programmieren oder Änderungen vornehmen, hast du zwei einfache Möglichkeiten:

Variante 1 • Mit Git

1. Lokal Änderungen committen & pushen:
git add . && git commit -m "Update" && git push

2. Auf dem Server nur einen Befehl ausführen:

/opt/snaphost/update.sh
Zieht automatisch den Code, updatet Pakete und startet den Dienst neu.
Variante 2 • Ohne Git (WinSCP)

1. Geänderte Dateien (z. B. public/ oder src/) einfach mit WinSCP per Drag & Drop überschreiben.

2. Auf dem Server den Dienst kurz neustarten:

systemctl restart snaphost
Dauert ca. 1 Sekunde. Alle Datenbank-Einträge und Apps bleiben erhalten.
